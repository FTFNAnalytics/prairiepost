## What failed, and what this pin changes

The 388f1bd roll stopped at the nginx test before the schema step and
put the vhosts and cron files back. Production was reported still on
`7cb82fb9c20a`, schema 25. The error was:

```
location "/router.php" is outside location "/admin/" in /etc/nginx/sites-enabled/edmontonecho:20
```

Verified against the five live blocks (Edmonton, Grande Prairie,
Kermode, Prairie Dispatch, Pacific Post) and against portagepress,
which already has the front controller and was not rewritten. Each of
the five nests its first `location ~ \.php$` inside
`location ^~ /admin/`, and also has a top-level `location /` with
`try_files $uri $uri/ =404`. `pp_before_php_handler` inserted
`location = /router.php` in front of every PHP handler, so the new
location landed inside `/admin/`. nginx refuses a location whose name
is not under its parent. The same pass rewrote every
`try_files $uri $uri/ =404`, including the one inside `/admin/`.

This pin inserts only beside a PHP handler that is a direct child of
`server`, and rewrites only the server-level `location /` fallback.
`location ^~ /admin/` keeps `try_files $uri $uri/ =404`. A second run
changes nothing. A generated block that already has
`location = /router.php` is still left alone, apart from the unlogged
`/tips` location. `tools/test-nginx-edits.sh` runs the editors on those
five files and on portagepress, then `nginx -t`.

## The stopped 388f1bd roll

The failure was before the migration, and the run said it restored
every vhost and cron file. The script demands `PP_UPGRADE_ABANDON` only
when an **enabled vhost still names** an unfinished release (a
directory with `.pp-roll-baseline` and neither `.pp-roll-complete` nor
`.pp-roll-held`). Leftover trees that nothing serves do not arm that
check. Setting `PP_UPGRADE_ABANDON` when no vhost names that commit
stops the new roll instead:

```
PP_UPGRADE_ABANDON names 388f1bd03ffe, but no vhost names a stopped roll of that commit — nothing changed
```

Before the command, look:

```bash
grep -n prairiepost-388f1bd /etc/nginx/sites-enabled/* || echo "NO-VHOST-NAMES-388f1bd"
ls -d /var/www/prairiepost-388f1bd03ffe-* 2>/dev/null || echo "NO-LEFTOVER-TREE"
```

- **No enabled vhost names `prairiepost-388f1bd03ffe-`.** This is what
  the failed run reported. Do **not** set `PP_UPGRADE_ABANDON`. The
  trees `/var/www/prairiepost-388f1bd03ffe-shared` and
  `-civismedia`, if they are still there, are not served. Leave them
  until this roll has verified, then remove them. Do not point a vhost
  at them.
- **An enabled vhost still names that directory**, and it has
  `.pp-roll-baseline` without `.pp-roll-complete` or `.pp-roll-held`.
  Then this roll must set
  `PP_UPGRADE_ABANDON=388f1bd03ffe6483a61eea099029af5c26a3e41b`
  beside the new pin (DEPLOY.md §11). Do not finish 388f1bd at its own
  commit: that upgrader fails the nginx test again.

## The command

```bash

curl -fsSL -o "$W/upgrade-papers.sh" \
  "https://raw.githubusercontent.com/FTFNAnalytics/prairiepost/$PIN/tools/vps/upgrade-papers.sh"
sha256sum "$W/upgrade-papers.sh"
# must be dd1fb181fb67ed53c347af84515d4f7c7a4f0dac4b7daf14a5f53f5564b4a0ec

# Only if an enabled vhost still names prairiepost-388f1bd03ffe-:
# ABANDON=388f1bd03ffe6483a61eea099029af5c26a3e41b
# Otherwise leave ABANDON unset.

systemd-run --unit=pp-roll-$(date +%s) --wait --pipe \
  env PP_UPGRADE_SHA=$PIN ${ABANDON:+PP_UPGRADE_ABANDON=$ABANDON} \
  bash "$W/upgrade-papers.sh"
```

The log is `/var/log/prairiepost-upgrade/roll-<stamp>.log`. A dropped
session does not stop `systemd-run`. If this roll stops after the
migration, run **this** pin again: it finishes rather than starting
over. Do not abandon this pin in order to retry 388f1bd.
